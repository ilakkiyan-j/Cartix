Cartix Engineering Documentation

Complete reference for the Cartix Model Context Protocol (MCP) server: Architecture, tool schemas, sanitization, rate limiting, and agent integration.

Overview & Motivation #

Modern merchants maintain their mission-critical business data inside e-commerce platforms like WooCommerce. However, autonomous AI agents cannot directly query raw store databases without encountering massive security risks, rate-limit bans, credential exposures, and context-window token overflows.

Cartix serves as the secure, read-only Model Context Protocol (MCP) bridge between AI reasoning agents (Claude Desktop, Cursor, LangChain, custom agents) and WooCommerce REST endpoints.

Clean Separation of Concerns
Cartix handles credential isolation, token bucket rate limiting, jittered retries, input schema validation, and customer PII sanitization. The AI agent focuses purely on reasoning, analysis, and user interaction.

Quick Start & Setup #

Follow these steps to clone and run Cartix on your development machine:

bash — installation 
# 1. Clone repository & enter directory
git clone https://github.com/ilakkiyan-j/Cartix.git
cd Cartix

# 2. Install dependencies
npm install

# 3. Create environment configuration
cp .env.example .env

# 4. Build TypeScript bundle
npm run build

# 5. Start the server (runs streamable-http or stdio depending on MCP_TRANSPORT)
npm start

Claude Desktop Integration #

Claude Desktop communicates with Cartix using the standard stdio transport. Add the server entry to your Claude Desktop configuration file:

Config Location:

  • macOS: ~/Library/Application Support/Claude/claude_desktop_config.json
  • Windows: %APPDATA%\Claude\claude_desktop_config.json
claude_desktop_config.json 
{
  "mcpServers": {
    "cartix": {
      "command": "node",
      "args": ["/absolute/path/to/Cartix/dist/src/index.js"],
      "env": {
        "WOOCOMMERCE_URL": "https://store.example.com",
        "WOOCOMMERCE_CONSUMER_KEY": "ck_...",
        "WOOCOMMERCE_CONSUMER_SECRET": "cs_...",
        "MCP_TRANSPORT": "stdio"
      }
    }
  }
}

Architecture & Transport Protocols #

Cartix conforms strictly to the Model Context Protocol (MCP) specification. All tool requests and responses are encapsulated in standard JSON-RPC 2.0 frames across three supported transports:

TransportBest ForSpecification & Behavior
stdioClaude Desktop, Cursor IDE, CLI agentsStandard input/output piping over process spawn. Fast, zero network port overhead.
streamable-httpWeb agents, microservices, DockerStateless chunked HTTP endpoint at /mcp. Highly scalable for multi-tenant setups.
sseBrowser agents, streaming interfacesServer-Sent Events streaming at /sse with HTTP POST message forwarding.

Security & Privacy Guardrails #

Cartix enforces enterprise security at every layer of the proxy lifecycle:

1. Server-Side Credential Isolation

WooCommerce API keys are loaded once into server memory from environment variables. The MCP input schemas exposed to AI models require only business query parameters — keys are never passed through prompt contexts.

2. Automatic PII Redaction

Customer records are sanitized before returning JSON payloads:

  • Email Masking: alexander@example.com becomes a***r@example.com.
  • Physical Address Stripping: Street addresses and apartment details are stripped; only country and state are preserved for shipping zone reasoning.

3. Secret Redaction in Logs

All loggers automatically intercept and redact sensitive token patterns (\bck_[a-zA-Z0-9_-]+ and \bcs_[a-zA-Z0-9_-]+) to guarantee secrets are never written to disk, console, or observability sinks.

Rate Limiting & Reliability #

To safeguard store infrastructure from high-concurrency agent loops:

  • In-Memory Token Bucket: Regulates outbound request bursts with configurable capacity and refill intervals.
  • Exponential Backoff with Full Jitter: Transient network errors and 5xx responses are retried using randomized jitter delays (sleep = rand(0, min(max_delay, base * 2^attempt))).
  • 429 Retry-After Header Parsing: Explicitly respects upstream WooCommerce throttling directives.

MCP Tools Specification #

Cartix registers 5 production-ready, read-only MCP tools implemented in TypeScript with Zod validation.

search_orders READ-ONLY #

Search and filter WooCommerce merchant orders by status, date range, and pagination with automatically sanitized customer records.

Input Schema Parameters

ParameterTypeRequiredDefaultDescription
statusstringNo—Filter by status: pending, processing, on-hold, completed, cancelled, refunded, failed, any
date_fromstringNo—Inclusive start datetime in ISO 8601 format (e.g. 2026-10-01T00:00:00Z)
date_tostringNo—Inclusive end datetime in ISO 8601 format (e.g. 2026-10-02T23:59:59Z)
pageintegerNo1Page number for pagination (minimum: 1)
limitintegerNo20Maximum number of orders to return (1–100)
search_orders Response Payload (Sanitized) 
{

    {
      "id": 1042,
      "status": "pending",

      "currency": "USD",

        "email": "a***e@example.com"

      "item_count": 2
    }
  ],
  "pagination": {
    "page": 1,
    "limit": 20,
    "total": 1,
    "total_pages": 1

AI Demo Agent #

Cartix includes a runnable multi-turn AI agent in demo/agent.ts. The agent interacts over live MCP tools using Google Gemini (gemini-2.5-flash) with an automatic offline fallback to local heuristic reasoning when API keys are not provided.

bash — run demo agent 
# Interactive multi-turn CLI agent
npm run demo

# Execute all 6 automated evaluation scenarios
npm run demo -- --all

Testing & Quality Assurance #

The automated test suite runs on Vitest and contains 60 automated tests across 10 test files, guaranteeing comprehensive coverage:

  • Schema & Input Validation: Strict Zod constraint checks for IDs, status enums, date strings, and pagination.
  • Error Mapping: Deterministic HTTP 400, 401, 404, 429, and 500 error code translations into MCP error envelopes.
  • PII Sanitization: Regular expression tests verifying zero email or address leakage.
  • Token Bucket & Backoff: Simulating upstream 429 responses and verifying jittered exponential retry delays.
  • End-to-End MCP Handshake: Verification over stdio and streamable-http JSON-RPC 2.0 endpoints.
bash — vitest test runner 
# Execute complete test suite
npm test

# Run tests in watch mode during development
npm run test:watch

Docker Containerization #

Deploy Cartix inside a hardened, unprivileged Node 20 Alpine container for cloud or internal microservice environments:

bash — docker deployment 
# Build optimized container image
docker build -t cartix-mcp .

# Run container with environment configuration
docker run -d -p 3000:3000 \
  -e WOOCOMMERCE_URL=https://store.example.com \
  -e WOOCOMMERCE_CONSUMER_KEY=ck_... \
  -e WOOCOMMERCE_CONSUMER_SECRET=cs_... \
  -e MCP_TRANSPORT=streamable-http \
  --name cartix-mcp-server \
  cartix-mcp

Explicit Operational Boundaries #

Cartix is architected with a strict zero-mutation security contract. The server does not register any tools capable of modifying merchant data.

Immutable Guarantee
Cartix will strictly refuse any operations attempting to create orders, modify customer accounts, alter inventory stocks, capture payments, or execute raw unvalidated REST calls.
